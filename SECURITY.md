# Security Policy

Project ECHO stores private journal entries and other personal memories locally. Security reports are taken seriously.

## Supported versions

Security fixes are generally intended for the latest version on the `main` branch. Older copies may not receive fixes.

## Reporting a vulnerability

Please do not publish passwords, private capsule contents, encryption keys, database files, or a working exploit in a public issue.

Instead, contact the repository owner privately through GitHub's profile contact options and include:

- A clear description of the suspected vulnerability.
- The affected version, operating system, and relevant configuration.
- Steps to reproduce the issue, using test data only.
- The potential impact and any suggested mitigation.

If private contact is unavailable, open a minimal public issue asking for a private reporting channel. Do not include exploit details or personal data.

## What to include in a report

Please use a disposable test vault and synthetic content. Redact usernames, local file paths, tokens, passwords, and any personal information from screenshots and logs.

## Scope and expectations

Examples of security-relevant concerns include unauthorized access to vault contents, weaknesses in encryption or key handling, unsafe backup import behavior, and sensitive data exposure through logs.

Please allow reasonable time for investigation and a fix before sharing technical details publicly. Reports are welcome, and responsible disclosure helps keep users' memories private.
